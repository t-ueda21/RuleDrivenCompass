# Compass ワークフロー

この README の参照先に従う。導入先の指示、仕様、受け入れ条件、既存の検証手順を確認し、今回の依頼範囲を確定する。

すべての工程で、人間に確認するとき、回答を受けたとき、または決定を成果物に反映したときは、[課題管理 Skill](issue-tracking/SKILL.md) に従って共通の課題管理表を更新する。

1. **作業前。** [Compass の README](../README.md) を確認し、[作業前 Skill](preflight/SKILL.md) に従って４項目を１つのコードブロックで提示する。分類に必要な読み取りは提示前に行い、依頼された変更や検証の実行は提示後に開始する。
2. **参照先の選択。** [工程別の参照先](phase/README.md) で開発区分と作業範囲に該当する工程の Skill を選ぶ。関連技術のガイドと、変更の影響に応じた確認ルールは Compass の README から選ぶ。該当する資料の本文を読み、同じ確認事項は一度の検証で扱う。対応資料が未整備または参照不能の場合は、プロジェクトの既存指示、仕様、検証手順を参照する。
3. **作業・検証。** 依頼された範囲の工程 Skill、技術ガイド、確認ルールに沿って、受け入れ条件に対応する作業・検証を依頼範囲で実施する。成果物の作成・更新では、工程のテンプレートと[共通の記録・確認ルール](../documents/document-records.md)を使う。必須欄と補足欄の記録を確認し、必須項目が不足する工程は未完了として扱う。レビューのみの依頼では、既存の成果物と証跡を全項目に照合し、不足を報告する。テンプレートの利用方法は工程の README を参照する。Excel出力を依頼された場合は、[Excel出力手順](../documents/excel-export.md)に従う。適用条件を左右する事実が不明なら確認し、作業中に技術や影響範囲が判明した場合は README の適用条件を再照合する。
4. **作業後。** README から作業後 Skill を参照する。参照できない場合は、作業結果、実施した検証と結果、未実施の検証と理由、未確認事項、次に推奨する作業の５項目を毎回報告する。未実施と失敗を区別し、追加作業が不要なら「追加作業なし」と記載する。参照できない資料が作業や検証に影響した場合は、影響を報告に含める。
