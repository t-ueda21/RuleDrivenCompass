# 単体試験

作業範囲に「単体試験」が含まれるときに適用する。

## 成果物テンプレート

[単体試験書テンプレート](references/template.md) を使って、担当範囲の成果物を作成・更新し、記録項目を確認する。レビューでは対象の成果物をテンプレートの項目と照合する。

テンプレートの必須欄に確認した内容または根拠の参照先を記録する。補足欄にも内容または適用結果と理由を記録する。完了前は[共通の記録・確認ルール](../../../documents/document-records.md)に沿って全項目を確認する。

## 実施手順

[試験の初回記録](../../../documents/test-history.md)を適用する。実行前に対象版・全ケース・手順・入力・期待結果を登録し、各ケースの最初の操作を呼ぶ直前に実行 ID を取得する。手順エラーや実施不能を含む初回結果とログを直後に保存し、独立した他のケースを続ける。計画の初回一巡を終えてから設計・実装・手順・期待値・データの修正と再試験を行う。

1. 詳細設計の仕様 ID ごとに、対象部品に必要な正常値・境界値・異常値を選び、期待する戻り値・例外・副作用を仕様から定める。
2. 導入先の既存テストと入力データを確認し、不足するケースのデータとテストコードを作成する。少数の値はテストコードに直接記述できる。再利用するファイルは導入先の既存の試験データ置き場に保存する。配置が未定の場合は `tests/fixtures/<機能名>/` を使う。
3. 用意した入力で対象部品を単独実行し、実際の結果を期待結果と照合する。ケース ID ごとに入力値または作成元、実行 ID、実行結果と証跡を記録する。生成データを使う場合は再生成条件も残す。

## 必須項目

- 試験ケースを参照できるケース ID・項目名。実行した場合は実行 ID、対象版・環境、証跡の参照先
- 対応する詳細設計の項目名または ID と試験対象の部品
- 前提と実行に使用する入力値・ファイル・生成処理のいずれか、詳細設計に基づく期待結果
- 試験コードまたは手順、実行結果、合否、対象範囲の判定

## 詳細な確認

境界値、異常系、依存先の代替、再試験の対象を決めるときは、[単体試験の確認基準](references/checkpoints.md) を参照する。

## 完了条件

試験書と作業後報告に、全件初回合格の場合も初回と最終の内訳を必ず載せる。再試験は同じケース ID に新しい実行 ID を付ける。元の条件・証跡の読み違いは、当初判定を保持して同じ実行 ID に再判定の根拠を追記する。

対象部品について、仕様 ID、ケース ID、実際に使用した入力、期待結果、実行結果・証跡を対応づけ、必要な試験の合否を判定できる。未実施の試験は理由と未確認の挙動を記録する。
