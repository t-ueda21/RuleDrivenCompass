# 実装の確認基準

- **仕様との追跡。** 変更した成果物と、対応する要件、設計または試作の仮説を照合する。差分の参照先は変更箇所を再確認できるものを使う。
- **設計変更。** 実装で決まった設計上の差異は、理由と影響先を記録する。既存の設計書や確認済みの決定に関係する場合は、該当箇所を参照する。
- **依存・設定。** ライブラリ、ランタイム、設定の追加・更新があれば、採用理由、対象版、影響する環境を記載する。公開 API や保存データに影響する確認は、プロジェクトの適用ルールに従う。
- **検証。** 今回実行したコマンド、対象、結果を区別して記録する。実施できなかった確認は理由と影響を残す。
- **引き渡し。** 後続工程が仕様、差分、実行方法、未確認事項を参照できるようにする。
