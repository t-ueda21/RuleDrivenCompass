# 調査の確認基準

| 調査の種類 | 確認基準 |
| --- | --- |
| 現状確認 | 仕様、実装、実行結果のどれを確認したか、対象版と環境を記載する。記述が一致しない場合はそれぞれの結果と影響を記録する。 |
| 不具合の再現 | 操作、入力、事前状態を揃える。期待した挙動、実際の挙動、証跡を記録し、正常時との相違を確認する。 |
| 原因分析 | 仮説ごとに根拠と反証を評価する。取得した証拠で示せる範囲を結論に記載する。 |
| 実現可能性 | 選択肢を同じ目的・制約で比較する。検証条件、成立条件、未評価のコストや依存先を明示する。 |
| 業務フロー | 担当者、開始条件、活動の順序、分岐と例外を示す。関係者の役割と現行手順の共有が必要な場合に使う。 |

人間への確認が必要になったら、課題管理表の課題 ID を未確認事項から参照する。
