# 課題管理表の記録項目と状態

| 状態 | 使用する条件 | 対応する記録 |
| --- | --- | --- |
| 確認待ち | 回答待ち、または判断が保留 | 何を誰にいつ確認したかと、判断に必要な事項を記録する。 |
| 対応待ち | 決定は確定し、反映または反映確認が残る | 回答・決定と根拠を記録し、反映予定の文書・コード・試験を追跡する。 |
| 完了 | 必要な反映を確認できた、または追加対応不要と確定 | 反映確認の結果と証跡、または対応不要と決まった根拠を記録する。 |

## 記録と更新

- 判断根拠には、確認時の依頼、回答、検討資料、決定の前提などを参照できる情報を記載する。
- 複数の工程・成果物へ反映する場合は、同じ課題 ID に反映先の項目 ID と確認結果を追記する。反映先ごとに予定・反映済み・確認済みを確認する。
- 判断が保留になった場合や決定を再確認する場合は、既存の行に更新内容を記録し、現在の状態を判定し直す。

## 必須と補足

- 確認時の必須項目は課題 ID、発生フェーズ、状態、確認事項、確認先、確認日。回答後は回答・決定日、回答・決定内容、判断根拠・参照先も記録する。
- 反映が必要な課題を完了にするときは、反映先と確認結果・証跡を記録する。対応不要と決まった場合は、決定の根拠と「対象外（追加対応が不要と決定）」を記録する。
- 影響する項目・範囲と次の確認・対応予定も毎回記録する。回答待ちの欄は「未確認（回答待ち）」のように理由を添える。既知の内容を記録し、確認後に同じ行を更新する。

## 既存台帳の移行

従来の６列は、新しいテンプレートの「課題 ID」「発生フェーズ」「確認事項」「回答・決定内容」「反映先」「状態」へ対応させる。課題 ID、記録内容、反映先の参照を引き継ぐ。過去の記録に未記載の情報を追加するときは、確認できた内容を記載する。確認できない情報は「未確認（移行前の台帳に記録なし）」のように理由を記録する。過去の状態と課題 ID を引き継ぐ。
