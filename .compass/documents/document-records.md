# 成果物の記録・確認ルール

選択した工程のテンプレートを基準に、必須欄と補足欄のすべてを記録する。導入先の既定書式を使う場合は、各テンプレート項目に対応する欄と根拠を確認する。

| 区分 | 記録の基準 |
| --- | --- |
| 必須 | 対象の条件・結果などの具体的な内容、または確認できる資料・証跡の参照先を記載する。空欄・仮記入・未確認のままの場合は工程を未完了として扱う。 |
| 本番必須・試作必須 | 今回の開発区分に該当する内容を必須として記録する。もう一方の見出しには「対象外（今回はPoC）」など、今回の区分と理由を記録する。 |
| 補足・該当時 | 関係する条件と確認結果を記録する。内容を記録できない項目にも、適用結果と理由を残す。欄が属する章全体に同じ結果を適用する場合は、章見出しの直下に結果と理由を記録する。 |

## 適用結果の記録

- 該当なし（対象に外部連携が存在しないことを確認）
- 対象外（今回の依頼は試験書のレビューまで）
- 未確認（検証環境の利用条件が未確定。課題 Q-012）
- 未実施（対象ビルドの配備予定が未確定）
- 判定不能（ログに判定に必要な項目が含まれていない）

未確認・未実施・判定不能は、理由と影響、分かる場合は次の確認先または課題 ID を記録する。表に「状況」と「理由」の列があるときは、それぞれの列に記録する。案件固有の内容は、今回の実施範囲に該当する指定欄に記録する。必須の根拠や完了条件に影響する未確認事項は、工程の完了判定に含める。

## 完了前の確認

1. 必須欄に実際の内容か根拠の参照先があることを照合する。要件・設計・試験の関連 ID と証跡の内容も確認する。
2. 各補足欄に記録または理由があることを確認する。標準テンプレートを使った Markdown は [記入状況の確認スクリプト](scripts/check_document.py) で確認する。指定書式を使う場合やスクリプトが利用できない場合は、対応欄を同じ条件で確認する。
3. 工程の完了条件を確認し、欠けている必須項目や確認が残る事項を報告する。レビューのみの依頼では、対象の文書と証跡から確認した結果を報告する。

## 記入状況の確認スクリプト

プロジェクトのルートから実行する。標準テンプレートの見出しと欄を使った Markdown を対象とする。本番・試作で必須欄が変わる工程には `--mode production` または `--mode poc` を指定する。Excel出力は記入途中の文書にも使用できる。

```powershell
uv run .compass/documents/scripts/check_document.py requirements-definition docs/requirements.md --mode poc
uv run .compass/documents/scripts/check_document.py integration-testing docs/integration-test.md
```

スクリプトは見出し、表の列、記入値、補足欄の理由の有無を確認する。基本設計では、要件との対応で参照した契約と、契約表の内容・版・確定状況も照合する。記載した根拠の正しさ、参照先の内容、工程の合否は文書・証跡の確認で判定する。
