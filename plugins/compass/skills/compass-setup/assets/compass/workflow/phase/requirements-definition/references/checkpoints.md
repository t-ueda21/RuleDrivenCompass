# 要件定義の確認基準

- **要求との対応。** どの利用者や既存資料が要求元かを確認する。決定が保留の場合は、該当する要件と課題 ID を対応づける。
- **受け入れ条件。** 実行前の状態、操作または入力、観測可能な結果を記載する。性能などの数値条件は測定環境と閾値も明確にする。
- **品質要件・制約。** 性能、権限、信頼性、互換性など、変更に影響する事項を特定する。機能要件と同じように試験または確認方法を参照できるようにする。
- **試作。** 実現可能性に関する仮説、確認方法、成功条件を記載する。試作で確認する範囲と、残す課題を明確にする。
- **ユースケース。** 複数の利用者や外部システムの役割を共有する場合はユースケース図を使う。正常・代替・例外フローの具体的な条件は記述または参照先で確認する。
