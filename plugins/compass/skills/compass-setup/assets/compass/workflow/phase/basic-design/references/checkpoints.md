# 基本設計の確認基準

| 確認対象 | 判断基準 |
| --- | --- |
| システムの構成 | 構成要素の責務、管理するデータ、接続先、対象外との境界を識別できる。構成や接続が変わる場合はアーキテクチャ図で範囲を確認する。 |
| 要素間の契約 | 呼出元と接続先に加え、前提、要求形式、応答、外部から観測できる状態変化、仕様の版・参照先、確定状況を記載する。結合試験で正常時・異常時の期待結果を判定できる粒度にする。 |
| タイムアウト・再試行 | 影響する契約では、発生条件、再試行の可否、重複時の応答や副作用を記載する。同じ要求を再送した場合の扱いを条件付きで確認する。 |
| 互換性 | 既存契約の変更点と影響する利用者・呼出元を特定する。既存仕様の維持、移行、扱う異常条件を確認する。 |
| 画面・フロー | 画面分岐や利用者の遷移を変更する場合は画面遷移図を参照する。条件と遷移先を設計の参照項目に結び付ける。 |
| 主要な設計判断 | 代替案、選択した理由、依存関係と後工程への影響が確認できる。 |

設計の確認結果は、対象の要件・構成要素・契約と根拠を結び付けて記録する。未確定事項は今回の設計と後続工程に影響する内容を記録する。

要件との対応・契約表・結合試験では同じ契約 ID を使う。ID がない場合は同じ項目名を使う。部品内部の入力処理やアルゴリズムを変更する場合は、対応する基本設計項目を詳細設計から参照する。
