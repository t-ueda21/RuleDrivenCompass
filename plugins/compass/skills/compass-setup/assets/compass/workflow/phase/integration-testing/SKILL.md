# 結合試験

作業範囲に「結合試験」が含まれるときに適用する。

## 成果物テンプレート

[結合試験書テンプレート](references/template.md) を使って、担当範囲の成果物を作成・更新し、記録項目を確認する。レビューでは対象の成果物をテンプレートの項目と照合する。

テンプレートの必須欄に確認した内容または根拠の参照先を記録する。補足欄にも内容または適用結果と理由を記録する。完了前は[共通の記録・確認ルール](../../../documents/document-records.md)に沿って全項目を確認する。

## 実施手順

[試験の初回記録](../../../documents/test-history.md)を適用する。実行前に対象版・全ケース・手順・入力・期待結果を登録し、各ケースの最初の操作を呼ぶ直前に実行 ID を取得する。手順エラーや実施不能を含む初回結果とログを直後に保存し、独立した他のケースを続ける。計画の初回一巡を終えてから設計・実装・手順・期待値・データの修正と再試験を行う。

1. 基本設計から、今回つなぐ要素と確認する契約を特定する。画面と API、API と DB など、同じシステム内の境界も対象にする。
2. 契約ごとに、入力と実行前の状態、期待する応答と更新後の状態を定める。導入先の既存データを照合し、足りない要求データ、取込ファイル、試験 DB の初期データなどを作成する。共有ファイルは導入先の試験データ用ディレクトリ（配置が未定なら `tests/fixtures/<機能名>/`）に置く。
3. 試験ごとに必要な初期状態を再現し、用意したデータを実際の取込処理や API に渡して、対象の要素を接続した状態で実行する。応答と接続先の状態を照合する。例えば全件取消の契約なら、エラー応答と保存件数・内容の両方を確認する。
4. ケース ID と使用データ、初期化方法、実行 ID、実測結果・ログを対応づける。代替した接続先がある場合は、実際に確認できた境界と未確認の境界を示す。

## 必須項目

- 試験ケースを参照できるケース ID・項目名。実行した場合は実行 ID、対象版・環境、証跡の参照先
- 対応する基本設計の契約の項目名または ID、接続した要素と境界
- 試験環境・使用データと初期状態の再現方法、呼び出し条件、契約に基づく期待結果
- 試験手順またはコード、実行結果、合否、対象範囲の判定

## 詳細な確認

代替接続、タイムアウト・再試行、境界をまたぐ副作用、再試験を扱うときは、[結合試験の確認基準](references/checkpoints.md) を参照する。

## 完了条件

試験書と作業後報告に、全件初回合格の場合も初回と最終の内訳を必ず載せる。再試験は同じケース ID に新しい実行 ID を付ける。元の条件・証跡の読み違いは、当初判定を保持して同じ実行 ID に再判定の根拠を追記する。

使用データと実行証跡をケース ID から参照でき、対象の接続で基本設計の契約を満たしたか判定できる。未実施の試験や未確認の境界は理由とともに報告する。
