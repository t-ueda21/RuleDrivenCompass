# 操作から要件を確定する記録例

以下は経費精算を使った架空の例。実際の記録には、その案件で操作された版と本人の回答を使う。

| 時点 | 利用者への提示・回答 | 記録 |
| --- | --- | --- |
| 初回提示 | 「v1で交通費を入力し、確認画面で金額を修正してください」 | Q-001を作成し、要件定義書に試作の参照先と「確認待ち」を記録 |
| 操作後 | 利用者「金額を直すと、利用日まで入力し直しになる。日付は残してほしい」 | Q-001に発言・確認者・日付を記録。R-02に修正時の入力保持を追加。v2を提示し「再確認待ち」 |
| 再操作後 | 利用者「v2で金額を変えても日付が残った。この動作でよい」 | Q-001にv2と回答を追記。「採用」とし、R-02・AC-02への反映を確認 |

本番のAC-02は「利用日を入力済みの状態で、確認画面から金額だけを変更したとき、再表示された利用日が元の値と一致する」。PoCなら同じR-02を「仮説と成功条件」の確認対象に記載し、対応する条件IDをレビュー行に記録する。画面間の正式な遷移図は基本設計で作成する。
