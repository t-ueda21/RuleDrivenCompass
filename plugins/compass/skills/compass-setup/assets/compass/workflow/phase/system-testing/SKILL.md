# 総合試験

作業範囲に「総合試験」が含まれるときに適用する。

## 成果物テンプレート

[総合試験書テンプレート](references/template.md) を使って、担当範囲の成果物を作成・更新し、記録項目を確認する。レビューでは対象の成果物をテンプレートの項目と照合する。

テンプレートの必須欄に確認した内容または根拠の参照先を記録する。補足欄にも内容または適用結果と理由を記録する。完了前は[共通の記録・確認ルール](../../../documents/document-records.md)に沿って全項目を確認する。

## 実施手順

1. 本番では要件定義の受け入れ条件を、試作では仮説と成功条件を参照し、試験対象の版・環境・利用シナリオを特定する。
2. シナリオの利用者・初期状態・操作対象を決め、導入先の既存データで条件を満たせるか照合する。不足する入力ファイル、利用者別のデータ、または必要な件数を生成する処理を導入先に作成する。共有ファイルの配置が未定なら `tests/fixtures/<機能名>/` を使う。生成条件が結果に影響する場合は、件数・日時・乱数シードなど該当する値を固定して記録する。
3. 用意したデータを使い、対象版の画面・API・CLIなど、シナリオで定めた利用手順を通して実行する。利用者から見た出力や最終状態を、受け入れ条件または試作の成功条件と照合する。
4. ケース ID ごとに、使用データ、実行 ID、観測結果・証跡、合否を記録する。実施できなかった確認は理由を示し、利用者による受入判断を求める場合はその結果も記録する。

## 必須項目

- 試験ケースを参照できるケース ID・項目名。実行した場合は実行 ID、対象版・環境、証跡の参照先
- 対応する要件と受け入れ条件、または試作の仮説と成功条件
- 試験対象の版・環境・利用シナリオ、使用データと初期状態、条件に基づく期待結果
- 実行結果、合否、対象範囲の判定。未実施項目がある場合は該当項目と理由

## 詳細な確認

本番とPoCの判定、非機能・回帰試験、利用者の受入判断を扱うときは、[総合試験の確認基準](references/checkpoints.md) を参照する。

## 完了条件

対象シナリオの使用データと実行結果を要件の受け入れ条件または試作の成功条件と対応づけ、判定と残る未確認事項を報告できる。
