# 総合試験の確認基準

- **本番。** 要件定義の受け入れ条件を参照し、利用者から見えるシステム全体の振る舞いと照合する。複数の機能で成立する利用シナリオは開始から終了まで確認する。
- **PoC。** 仮説ごとの成功条件を判定基準とする。試作環境、対象外の機能、確認できた範囲を記録する。
- **非機能要件。** 性能や権限などの確認が対象の場合は、負荷、対象者、環境、測定方法を基準と一緒に記載する。
- **回帰試験。** 今回の変更で影響する既存の利用シナリオを確認し、結果をケース ID から参照できる状態にする。
- **利用者の判断。** 受入判断を依頼された場合は、判断者、対象条件、判断結果を試験の実行結果と区別して記録する。
